# Epic 4: Панель состояния конвейера

Статус: открыт (ждёт проверки на живых запусках) · Создан: 2026-10-09

## Requirements (IMMUTABLE)

- R1. Скрытая страница `#/status` на сайте (без ссылок в меню и подвале) показывает работу конвейера за последние 48 часов.
- R2. По каждому запуску: время сбора и обработки; источники — ответили/ошибка; кандидаты и отобрано; итог обработки по статьям, постам и обсуждениям (опубликовано / пропущено / невалидно / нет выжимки / снято после 3 попыток).
- R3. По каждому источнику (лента, аккаунт X, обсуждения HN): последний статус и текст ошибки; за 48 часов — сколько материалов получено, опубликовано, пропущено.
- R4. По каждому материалу за 48 часов: тип, источник, оригинальный заголовок со ссылкой на оригинал, время публикации и сбора, полный текст или сниппет, итог с причиной (причина пропуска или ошибки проверки), ссылка на новость на сайте для опубликованных.
- R5. Данные — `site/data/status.json`, его пишет `izolenta merge` в routine; в нём нет текстов статей (только заголовки, ссылки, статусы).
- R6. Формат `news.json`, `posts.json`, `hn.json` не меняется; панель загружается независимо и не влияет на основные страницы.

## Success Criteria

- [ ] После запуска routine `status.json` содержит запуск со статистикой сбора и итогом по каждому материалу.
- [x] `#/status` показывает запуски, источники и материалы с фильтрами по итогу; 360px без горизонтального скролла (headless Edge: 360 и 1280 px, переполнение страницы нет, ошибок в консоли нет; таблицы прокручиваются внутри себя).
- [x] Повторная обработка материала (например, невалидно → опубликовано) обновляет его итог, а не дублирует строку (`test_status_reprocessed_material_updated_not_duplicated`).
- [x] Записи старше 48 часов удаляются (`test_status_keeps_only_last_48_hours`).
- [x] `pytest` (198), `node --test` (57), headless-проверки зелёные.

## Anti-patterns

- НЕТ текстов статей в `status.json` (они только в приватном `iizolenta-work`).
- НЕТ ссылок на `#/status` в меню и подвале (решение пользователя: скрытая страница).
- НЕТ изменения форматов основных файлов данных.

## Approach

`collect` дописывает в `pending.json` объект `stats` (по ленте/аккаунту/HN: ok, ошибка, записей, кандидатов, отобрано). `merge` собирает итог по каждому материалу (`KindResult.outcomes`), добавляет запись о запуске и обновляет записи материалов по id в `site/data/status.json`, удаляя старше 48 часов. Routine коммитит `status.json` вместе с остальными данными. Страница `#/status` — отдельный вид в `app.js`, данные грузятся только на ней.

## Key Decisions

| Question | Answer | Implication |
|---|---|---|
| Где панель | Скрытая страница на сайте | `#/status`, без ссылок; данные в публичном репозитории |
| Глубина истории | 48 часов | Хранение в `status.json` — 48 ч |

## Tasks

- `task-4-01-status.md` — статистика сбора, `status.json` и страница `#/status` (закрыта; данные и страница сделаны одной задачей — обе части маленькие и проверяются вместе)

## Ограничения

- Запуски, в которых нечего обрабатывать, routine завершает без коммита — в `status.json` их нет (это написано на странице).
- Кандидаты, не попавшие в лимит запуска, видны только числом («Новых» у источника), а не списком: они остаются в лентах и берутся следующими запусками.
