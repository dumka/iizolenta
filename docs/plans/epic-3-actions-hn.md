# Epic 3: Сбор в GitHub Actions, Hacker News и «Обсуждают на HN»

Статус: открыт · Создан: 2026-10-09

## Requirements (IMMUTABLE)

- R1. Сбор (`izolenta collect`) выполняется раз в час в GitHub Actions приватного репозитория `dumka/iizolenta-work` с полным доступом в интернет; код берётся из публичного `dumka/iizolenta`.
- R2. Рабочее состояние (`state/seen.json`, `state/pending.json`) хранится только в `dumka/iizolenta-work`. В публичном репозитории нет текстов чужих статей и нет `state/`.
- R3. Routine больше не ходит в интернет за новостями: только `git` (оба репозитория) и PyPI. Окружение переводится в режим сети Trusted (по умолчанию); добавление источников не требует правок окружения.
- R4. Hacker News — обычный источник новостей: статьи с первой страницы HN (с порогом очков) пересказываются как остальные, текст статьи берётся с любого домена.
- R5. «Обсуждают на HN»: для популярных обсуждений с первой страницы HN (пороги очков и комментариев — в `feeds.toml`) routine пишет русский заголовок и пересказ того, что обсуждают в комментариях (2-4 предложения), со ссылками на обсуждение и на статью.
- R6. Обсуждения хранятся в `site/data/hn.json` 3 дня; лимит на запуск — настройка; контракты `news.json` и `posts.json` не меняются.
- R7. На главной — компактный блок «Обсуждают на HN» под «Пишут в X» (3-4 обсуждения); пункт меню и страница `#/hn` со всеми обсуждениями.
- R8. Сбой сбора (Actions не запустился, упал, опоздал) не ломает сайт и routine: routine без свежего `pending.json` ничего не коммитит; повторной обработки одного и того же нет.

## Success Criteria (MUST ALL BE TRUE)

- [ ] `dumka/iizolenta-work` приватный, workflow `collect` отрабатывает по расписанию 3 раза подряд и коммитит `state/`.
- [ ] Routine работает в окружении с сетью Trusted и публикует новости, посты и обсуждения из `pending.json`, собранного в Actions.
- [ ] В публичном репозитории нет `state/`; `git grep` по текущему дереву не находит текстов статей.
- [ ] На сайте есть новость из статьи с HN (домен вне прежнего allowlist).
- [ ] Блок «Обсуждают на HN» на главной и страница `#/hn`; headless-проверки (1280, 360, без горизонтального скролла) зелёные.
- [ ] `pytest`, `node --test`, CI зелёные.

## Anti-patterns (FORBIDDEN)

- НЕТ текстов чужих статей и `pending.json` в публичном репозитории (решение пользователя).
- НЕТ режима сети Full у окружения routine и сетевых запросов агента к источникам (агент только пишет тексты).
- НЕТ персональных токенов (PAT) и секретов: сбор работает в Actions приватного репозитория со своим `GITHUB_TOKEN`, публичный код клонирует без авторизации.
- НЕТ пересказа статьи «по комментариям» в блоке HN: блок пересказывает обсуждение, а не выдумывает содержание статьи.
- НЕТ изменения форматов `news.json` и `posts.json`.

## Approach

`dumka/iizolenta-work` (приватный) содержит `state/` и workflow `.github/workflows/collect.yml` (cron `40 * * * *` + ручной запуск): checkout публичного репозитория в `app/`, checkout самого себя в `work/`, `uv sync --frozen`, `uv run python -m izolenta collect --config feeds.toml --state-dir ../work/state` из `app/`, коммит и push `work/state` с `GITHUB_TOKEN` (`permissions: contents: write`). Routine клонирует оба репозитория; шаг сбора из `PROMPT.md` убирается; `check` и `merge` работают с `--state-dir` рабочего репозитория и `--news/--posts` публичного; коммиты — в оба репозитория. Hacker News добавляется лентой (`hnrss.org/frontpage?points=...`), обсуждения — отдельным сборщиком через официальный HN API (`hacker-news.firebaseio.com`: история + первые по рейтингу комментарии), отдельный список `discussions` в `pending.json`, своя схема и `site/data/hn.json`.

## Design Discovery

### Key Decisions Made

| Question | User Answer | Implication |
|----------|-------------|-------------|
| Что делать с HN | A + C: сбор в Actions и блок «Обсуждают на HN» | R1-R7 |
| Где хранить состояние с текстами статей | Приватный `iizolenta-work` | R2; anti-pattern про публичный репозиторий |
| Где показывать HN | Главная + отдельная страница | R7 |
| Утренняя тишина источников | Добавлены The Decoder, AI News, MarkTechPost, The Register, r/LocalLLaMA (2026-10-09) | С переходом на Actions домены не нужно добавлять в allowlist |
| Блог Карпаты | Убран: Cloudflare-проверка режет облачные адреса | — |

### Context (2026-10-09)

- За ночь (21:00-07:00 UTC) во всех 16 прежних источниках вышло 9 записей — американские источники молчат в московское утро; конвейер исправен.
- FxTwitter из облака routine отвечает 404 на 3-5 случайных аккаунтов из 14 за запуск; один повтор поднял долю ответивших до 11/14. С переносом в Actions поведение может измениться.
- GitHub Free: около 2000 минут Actions в месяц для приватных репозиториев; сбор ~1 мин × 24 × 30 ≈ 720 мин.
