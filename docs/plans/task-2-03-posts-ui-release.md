# Task 2.3: Блок «Пишут в X» на сайте и выкатка эпика 2

Epic: `docs/plans/epic-x-posts.md` · Статус: closed (2026-10-08) · Оценка: 4 часа · Ветка: `x-posts` → `main` · Зависит от: Task 2.2 (closed)

## Goal

Дашборд показывает блок «Пишут в X» (главная, правая колонка над «Последними новостями»; на телефоне — после «Важного») и страницу `#/x` со всеми постами. Ветка `x-posts` слита в `main`, routine в облаке собирает и переводит посты, они видны на https://dumka.github.io/iizolenta/.

## Context

- `site/data/posts.json` (Task 2.2): `{"generated_at", "items": [{id, url, author_handle, author_name, published_at, text}]}`, от новых к старым, 3 дня. `text` может содержать абзацы через `\n\n`.
- Пользователь добавил в allowlist окружения `api.fxtwitter.com` и домены блогов (подтверждено 2026-10-08).
- Демо-данные для проверки — `posts.json` из пробного прогона Task 2.2 (7 постов, временная папка).
- Вёрстка и проверки — как в Task 3 эпика 1: только `textContent`, `isSafeUrl`, относительные пути, headless Edge через `puppeteer.connect`.

## Implementation

1. **`site/lib.js`**: `parseRoute("#/x")` → `{view: "x"}`; `postsStale(items, now, hours = 48)` → `true`, если список пуст или самый свежий `published_at` старше `hours`; `paragraphs(text)` → массив абзацев по пустой строке.
2. **`site/app.js`**:
   - `posts.json` грузится параллельно с `news.json` и независимо: ошибка загрузки постов не мешает новостям (на главной блок просто не показывается; на `#/x` — сообщение об ошибке с «Подклеить»).
   - Карточка поста: имя автора (жирным), `@handle` серым, время (`formatTime`), абзацы текста, ссылка «Открыть в X →» (`target="_blank" rel="noopener noreferrer"`, только при `isSafeUrl`).
   - Главная: в `aside` перед «Последними новостями» — блок «Пишут в X» с 5 последними постами и ссылкой «Все посты →» на `#/x`; если `postsStale` — вместо постов строка «Посты из X временно не обновляются».
   - `#/x`: заголовок «Пишут в X», все посты; пусто — «Пока тихо: свежих постов нет».
   - Рубрики (`#/ai`, `#/dev`, `#/business`) блок не показывают — он только на главной.
3. **`site/index.html`**: пункт меню «Пишут в X» (`href="#/x"`, `data-category="x"`); активность пункта — по маршруту.
4. **`site/styles.css`**: стили карточки поста в духе мини-карточек Ленты; блок визуально отделён (фон `--bg-soft`, отступы), длинные слова и ссылки — `overflow-wrap: anywhere`.
5. **`site/data/posts.json`**: начальный пустой `{"generated_at": null, "items": []}` (routine перезапишет).
6. **README**: блок «Пишут в X» в описании, домены в списке allowlist, `posts.json` в разделе routine.
7. **Выкатка**: тесты и headless-проверки в ветке → `git merge --no-ff x-posts` в `main` → push → деплой Pages → ручной запуск routine (`RemoteTrigger run`) → проверка лога: ошибки FxTwitter из облака, `check`, `merge`, коммит с `posts.json` → посты на сайте.

## Key Considerations (SRE review)

- **Независимость загрузки.** Падение `posts.json` (404 до первого запуска routine, битый файл) не должно ломать главную: `Promise.allSettled`, отдельное состояние.
- **Пустой `posts.json` против устаревшего.** Пустой список сразу после выкатки — это «Посты из X временно не обновляются» до первого запуска routine; приемлемо, запуск — сразу после выкатки.
- **Абзацы.** `text` с `\n\n` выводится отдельными `<p>`, а не через `innerHTML`/`<br>`.
- **Конфликт при слиянии.** Ветка не меняет `news.json`/`seen.json`; `posts.json` новый — конфликтов с коммитами routine быть не должно. Перед слиянием — `git pull` в `main`.
- **Окно между пушем и запуском.** После пуша в `main` следующий плановый запуск уже пойдёт с новым промптом; ручной запуск — для быстрой проверки.
- **Активный пункт меню.** Сейчас `updateChrome` выделяет рубрику по `route.category`; для `#/x` — по `route.view`.

## Anti-patterns

- НЕТ `innerHTML`, шаблонов с данными, внешних виджетов X (embed-скрипты X грузят трекеры и требуют внешних доменов).
- НЕТ изменения формата `news.json`.
- НЕТ слияния в `main` при красных тестах или проверках.
