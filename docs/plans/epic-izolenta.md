# Epic: Изолента — AI/IT-дашборд вместо lenta.ru

Статус: открыт · Создан: 2026-10-08

## Requirements (IMMUTABLE)

- R1. При открытии lenta.ru (любой путь, http/https) в Zen (Windows) и в Vivaldi 8.2+ (Android) пользователь попадает на дашборд «Изолента».
- R2. Список перехватываемых сайтов хранится в одном файле `sites.txt`, опубликованном вместе с дашбордом. Оба устройства читают его по URL. Добавить сайт = добавить строку, код не меняется.
- R3. Дашборд оформлен в духе lenta.ru: шапка с логотипом-словом, строка рубрик, главная новость, лента с временем, страница новости. Название «Изолента», логотип и торговые знаки Ленты не копируются.
- R4. Наполнение — мировые новости AI/IT из англоязычных источников. Каждая новость на русском: заголовок, лид из 1–2 предложений, выжимка из 3–5 абзацев, ссылка на оригинал с названием источника.
- R5. Рубрики: «ИИ и модели» (`ai`), «Разработка и инструменты» (`dev`), «Бизнес и стартапы» (`business`).
- R6. Обновление раз в час через Claude Code routine (облачный агент по подписке). API-ключ Anthropic не используется.
- R7. Детерминированную часть (сбор RSS, дедупликация, извлечение текста, слияние, валидация, очистка) делает Python-скрипт. Claude в routine только оценивает релевантность и пишет русские выжимки.
- R8. Хостинг — GitHub Pages, публичный репозиторий. Routine пушит данные прямо в `main`.
- R9. Хранится 7 дней новостей. Отклонённые как нерелевантные статьи запоминаются и повторно не оцениваются.
- R10. Число статей на один запуск ограничено настройкой (по умолчанию 15), чтобы контролировать расход подписки.
- R11. Дашборд читается на телефоне: адаптивная вёрстка, без горизонтального скролла.
- R12. Если на дашборд пришли через перехват, он показывает, какой сайт пытались открыть (LeechBlock передаёт URL через `#$U`).

## Success Criteria (MUST ALL BE TRUE)

- [ ] Ввод `lenta.ru` в Zen открывает дашборд (проверено вручную).
- [ ] Ввод `lenta.ru` в Vivaldi Android открывает дашборд (проверено вручную; при неудаче с LeechBlock работает запасной вариант с AdGuard).
- [ ] Добавление строки в `sites.txt` начинает перехватывать новый сайт на обоих устройствах без правки кода и без ручной настройки правил.
- [ ] Routine отработала по расписанию не меньше 3 раз подряд без вмешательства, и в `data/news.json` появились новые русские новости.
- [ ] Каждая новость в `news.json` проходит валидацию схемы (рубрика из R5, непустые заголовок/лид, 3–5 абзацев выжимки, ссылка http(s)).
- [ ] Новости старше 7 дней удаляются из `news.json` при слиянии.
- [ ] Отклонённая статья не попадает в `pending.json` повторно.
- [ ] Ошибка одной ленты или одной статьи (таймаут, 403, битый XML) не валит запуск, остальные обрабатываются.
- [ ] Все автотесты (pytest + node:test) проходят.
- [ ] На ширине 360px нет горизонтального скролла.

## Anti-Patterns (FORBIDDEN)

- ❌ НЕТ DNS/hosts-подмены lenta.ru (сертификат не совпадёт, а GitHub Pages выбирает сайт по Host и отдаст 404; исследование это подтвердило).
- ❌ НЕТ своего браузерного расширения на этом этапе (подпись AMO, ручная установка на Android, поддержка; LeechBlock NG закрывает задачу).
- ❌ НЕТ хардкода списка сайтов внутри правил расширений на каждом устройстве (нарушает R2; список один, в `sites.txt`).
- ❌ НЕТ вызовов Anthropic API и API-ключей (решение пользователя: только routine по подписке).
- ❌ НЕТ «всё делает промпт»: Claude не должен сам парсить RSS, дедуплицировать или редактировать `news.json` руками (недетерминированно, дорого по токенам, нельзя протестировать; это работа скрипта по R7).
- ❌ НЕТ записи в `news.json` невалидных записей (одна битая запись ломает весь дашборд; `merge` отбрасывает их).
- ❌ НЕТ бесконечных повторных попыток для статьи, на которой Claude постоянно ошибается (это сжигает лимиты; после 3 неудачных попыток статья помечается как просмотренная).
- ❌ НЕТ копирования логотипа, шрифтов-торговых знаков и названия «Лента.ру» (страница публичная; копируем стиль, а не бренд).
- ❌ НЕТ фреймворков и сборки во фронтенде (статичный HTML/CSS/JS, никакого build step: проще хостить и поддерживать).
- ❌ НЕТ доверия тексту статей как инструкциям (содержимое лент недоверенное; промпт routine явно запрещает выполнять указания из текста статей).

## Approach

Перехват делает готовое расширение LeechBlock NG. Оно есть в AMO (для Zen) и в Chrome Web Store (для Vivaldi Android), поддерживается (v1.8, сентябрь 2026) и умеет две нужные вещи. Первая: загружать список сайтов по URL (`sites.txt` с GitHub Pages). Вторая: перенаправлять на свой адрес с подстановкой исходного URL (`https://<user>.github.io/iizolenta/#$U`). Запасной вариант для Android — расширение AdGuard с trusted-правилом `$urltransform`.

Новости собирает Claude Code routine раз в час. Запуск устроен так. Скрипт `collect` скачивает RSS-ленты, отсеивает уже виденное, извлекает текст новых статей и пишет `pending.json` (не больше N штук). Claude читает его и пишет `summaries.json`: рубрику, русский заголовок, лид, выжимку и важность, либо `skip`. Скрипт `merge` валидирует результат, вливает его в `site/data/news.json`, чистит старое и обновляет состояние просмотренных статей. Затем коммит и пуш в `main`. GitHub Actions деплоит `site/` на Pages.

Дашборд — статичная страница: vanilla JS загружает `data/news.json` и рисует вёрстку в духе lenta.ru (главная, рубрики, страница новости через hash-роутинг).

## Architecture

```
RSS-ленты --> izolenta collect --> state/pending.json
                  ^                      |
                  | state/seen.json      v
                  |               Claude (routine): выжимки
                  |                      |
                  |                      v
            izolenta merge <-- state/summaries.json
                  |
                  v
          site/data/news.json --> git push main --> GH Actions --> GitHub Pages
                                                                      ^
   Zen / Vivaldi: LeechBlock NG -- sites.txt (с Pages) -- редирект ---+
```

Структура репозитория (план):
- `izolenta/` — Python-пакет: `config.py`, `feeds.py` (загрузка и парсинг), `extract.py` (текст статьи), `collect.py`, `merge.py`, `schema.py`, `__main__.py` (CLI `python -m izolenta collect|merge`).
- `feeds.toml` — список лент и настройки (лимит на запуск, срок хранения, максимальный возраст статьи).
- `state/seen.json` — просмотренные/отклонённые id с датами и счётчиком попыток.
- `state/pending.json`, `state/summaries.json` — рабочие файлы одного запуска (в `.gitignore`).
- `site/` — публикуется на Pages: `index.html`, `styles.css`, `app.js`, `sites.txt`, `data/news.json`.
- `routine/PROMPT.md` — инструкция для routine.
- `.github/workflows/pages.yml` — деплой `site/` на Pages.
- `tests/` — pytest с фикстурами лент; `site/tests/` — node:test для чистых функций рендера.

Схема записи в `news.json`:
```json
{
  "id": "sha1 канонического URL",
  "url": "https://...",
  "source": "TechCrunch",
  "published_at": "2026-10-08T10:15:00Z",
  "category": "ai | dev | business",
  "importance": 1,
  "title": "Русский заголовок",
  "lead": "1–2 предложения",
  "body": ["абзац 1", "абзац 2", "абзац 3"],
  "image": "https://... (необязательно)"
}
```

## Design Rationale

### Problem
Пользователь тратит время на новости и форумы, не связанные с работой. Цель — подменить привычный маршрут прокрастинации (lenta.ru) полезной лентой AI/IT-новостей на русском, не ломая привычку «зайти почитать новости».

### Research Findings

**Codebase:** пустой каталог, существующих паттернов нет.

**External:**
- Claude Code routines (https://code.claude.com/docs/en/routines.md): минимальный интервал — 1 час; суточного лимита запусков нет, лимит 100 scheduled-запусков в час на аккаунт; расход идёт из общего лимита подписки. Каждый запуск клонирует ветку по умолчанию заново, по умолчанию пушит в `claude/*`, но промпт может направить пуш в `main`. Расписание лучше ставить на `:07`, а не на `:00`.
- Сеть в облачном окружении (https://code.claude.com/docs/en/cloud-environments.md): по умолчанию режим Trusted, в нём нет доменов новостных лент. Нужен Custom со списком доменов или Full. Заблокированный запрос получает 403 `host_not_allowed`. Ленты лучше качать через curl/Python, а не через WebFetch.
- Setup script окружения кешируется, если укладывается примерно в 5 минут; в нём ставятся Python-зависимости (PyPI входит в список по умолчанию).
- LeechBlock NG (https://github.com/proginosko/LeechBlockNG): MV3, v1.8 (2026-09-27), есть в AMO и CWS. Свой URL блокировки с `$U`; «Load list of sites from URL» перечитывает список при старте браузера и при изменении настроек.
- Vivaldi Android 8.2 (2026-09-10) поддерживает расширения из Chrome Web Store (https://vivaldi.com/blog/vivaldi-on-mobile-8-2/), но не все API; LeechBlock на нём никто не проверял.
- Zen ставит дополнения из AMO; неподписанные, по-видимому, разрешены (`MOZ_REQUIRE_SIGNING=` в mozconfig), но нам это не нужно.
- lenta.ru нет в HSTS preload, заголовка HSTS он не отдаёт. DNS-подмена всё равно бесполезна: GitHub Pages выбирает сайт по Host и отдаст 404.
- AdGuard extension: `$urltransform` с `/^http.../` переписывает URL целиком (только в trusted-фильтрах); на Vivaldi Android проверено AdGuard.

### Approaches Considered

#### 1. LeechBlock NG + общий `sites.txt` (ВЫБРАН)
**What it is:** готовое MV3-расширение на обоих браузерах; список сайтов грузится по URL с Pages, редирект на дашборд с `#$U`.
**Pros:** без кода, поддерживается, один список на все устройства, передаёт исходный URL.
**Cons:** на Vivaldi Android не проверено → первая ручная проверка; запасной вариант — AdGuard.
**Chosen because:** выполняет R1, R2 и R12 с минимальной поддержкой; пользователь выбрал этот вариант.

#### 2. Своё расширение (ОТКЛОНЁН)
**What it is:** собственное WebExtension с declarativeNetRequest-редиректом.
**Why we looked at this:** полный контроль (кнопка «пропустить на 5 минут», статистика).
**Cons:** подпись AMO для Zen, установка через режим разработчика на Android, поддержка своими силами.
**REJECTED BECAUSE:** избыточно для R1/R2, которые закрывает готовое решение.
**DO NOT REVISIT UNLESS:** понадобятся функции, которых нет в LeechBlock (временный пропуск, статистика), или LeechBlock и AdGuard оба не заработают на Vivaldi Android.

#### 3. AdGuard extension, `$urltransform` (ЗАПАСНОЙ)
**Cons:** тяжёлое расширение, неудобный синтаксис правил, regex-экранирование.
**REJECTED BECAUSE:** LeechBlock проще. Остаётся запасным для Android.
**DO NOT REVISIT UNLESS:** LeechBlock не работает на Vivaldi Android.

#### 4. DNS: NextDNS / AdGuard DNS / hosts (ОТКЛОНЁН)
**REJECTED BECAUSE:** умеет только блокировать, а при подмене получаем ошибку сертификата и 404 от Pages.
**DO NOT REVISIT UNLESS:** никогда для редиректа; разве что как дополнительную блокировку без редиректа.

#### 5. Конвейер «всё в промпте» (ОТКЛОНЁН)
**What it is:** routine сама качает ленты через curl/WebFetch и правит `news.json`.
**REJECTED BECAUSE:** недетерминированно, дорого по токенам, нельзя протестировать, легко повредить JSON (нарушает R7).
**DO NOT REVISIT UNLESS:** скриптовый подход окажется несовместим с окружением routine.

#### 6. GitHub Actions + Anthropic API (ОТКЛОНЁН)
**REJECTED BECAUSE:** пользователь выбрал routine по подписке, без API-ключа (R6).
**DO NOT REVISIT UNLESS:** routines упрутся в лимиты подписки или будут выключены, и пользователь согласится на API.

### Scope Boundaries

**In scope:** перехват lenta.ru на двух устройствах, общий `sites.txt`, конвейер новостей, дашборд, деплой на Pages, routine, инструкция по настройке LeechBlock.

**Out of scope:** своё расширение; временный пропуск на сайт; статистика попыток зайти; персонализация; поиск по новостям; push-уведомления; iOS; другие браузеры.

### Open Questions
- Точные URL лент и их доступность из облачного окружения проверяются в Task 1.
- Режим сети окружения: Custom (список доменов; тексты HN-ссылок с произвольных доменов недоступны, берём сниппет) или Full (полные тексты, но шире поверхность для prompt injection). Решается при настройке routine.
- Работает ли LeechBlock на Vivaldi Android — проверка вручную после публикации дашборда.
- Хватит ли лимитов подписки на 24 запуска в сутки — смотрим расход за первые дни и при необходимости снижаем лимит статей.

## Design Discovery (Reference Context)

### Key Decisions Made

| Question | User Answer | Implication |
|----------|-------------|-------------|
| Телефон и браузер | Android + Vivaldi | Расширения из CWS (Vivaldi 8.2+), Chrome-совместимое решение |
| Браузер на ПК | Zen | Firefox-совместимое решение (AMO) |

| Частота | Каждый час | Расписание hourly на `:07`; лимит статей за запуск |
| Рубрики | ИИ, Разработка, Бизнес | R5; железо и безопасность не берём |
| Объём выжимки | Заголовок + лид + раскрытие | R4; нужен полный текст статьи, отсюда `extract` |
| Хостинг | GitHub Pages, публично | R8; бренд Ленты не копируем |
| Перехват | LeechBlock NG | Approach 1; AdGuard запасной |
| Дизайн целиком | Утверждён | — |
| Название (после публикации) | «ИИзоЛента» (ИИ + Лента), репозиторий `dumka/iizolenta` | Бренд на сайте и в промпте; Pages: `https://dumka.github.io/iizolenta/`; внутренние имена (`izolenta` пакет, `Izolenta Sans`) без изменений |

### Dead-End Paths
- DNS-подмена: HTTPS и выбор сайта по Host на Pages дают 404 или ошибку сертификата.
- «Vivaldi Android без расширений»: устарело, с 8.2 расширения есть.
- Redirector (Einar Egilsson): работает в Zen, но заброшен (AMO 2020, MV2) и не работает в Chromium, поэтому не подходит для Vivaldi.

### Open Concerns Raised
- Расход подписки при почасовом обновлении: настраиваемый лимит статей (R10) и контроль расхода в первые дни.
